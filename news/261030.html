767pxでレイアウトが崩れる問題を解決する

メディアクエリの見直しと、新しいCSS構文の採用判断

  • 2026/10/30 公開
  • 2026/10/30 更新

目次

  2. 767pxで発生した表示崩れ
  3. 調査で見つけた原因と解決方法
  4. 比較演算子を使ったメディアクエリ

先日、rat daysのレスポンシブ対応を進めていたところ、ブラウザの表示幅が767pxのときに、レイアウトが崩れる問題に直面しました。デスクトップ向けとモバイル向けでスタイルを切り替えるように設定していたにもかかわらず、想定どおりに表示されなかったのです。

メディアクエリとは

レスポンシブ対応では、画面の幅などの条件に応じてCSSのスタイルを切り替えるために、メディアクエリを使用します。例えば、次のように記述することで、画面幅が768px以上の場合と767px以下の場合で異なるスタイルを適用できます。

CSS 
/* デスクトップ向け */
@media (min-width: 768px) {
  /* 画面幅が768px以上のスタイル */
}

/* モバイル向け */
@media (max-width: 767px) {
  /* 画面幅が767px以下のスタイル */
}

767pxで発生した表示崩れ

実際にブラウザの表示幅を調整してみると、767pxのときだけレイアウトが崩れることがわかりました。768pxではPC向けのCSSが、766pxではSP向けのCSSがそれぞれ正常に適用されていたため、767px付近で何らかの問題が発生していると考えられます。

本来であれば、画面幅に応じてPC向けとSP向けのスタイルが適切に切り替わるはずです。しかし、今回はその境界にあたる767pxでレイアウトが正常に表示されませんでした。CSSの記述に問題があるのか、それともブラウザやWindowsの表示設定が関係しているのか、原因がすぐにはわからなかったため、まずはオンラインで情報を調べ、自分と同じような問題が起きていないかを確認することにしました。

調査で見つけた原因と解決方法

「767pxで表示が崩れる」と検索したところ、teratailに投稿された「サイトのデザインがwidth767pxで崩れるのは何故なのか？」という質問を見つけました。自分と同じように767pxでレイアウトが崩れるという内容で、回答を読み進めるうちに、今回の問題にも共通する原因があることに気づきました。

原因の一つは、Windowsのディスプレイ設定で拡大縮小率が150%になっていたことです。さらに、この設定によってブラウザが扱う表示幅に小数点以下の値が生じ、従来のメディアクエリでは、どちらの条件にも該当しない幅が発生していたことがわかりました。

参考ページの投稿者は、Windowsのディスプレイ設定を変更することで問題を解決したとしています。しかし、表示設定を変更するだけでは、別の環境で同じことが起きる可能性が残ります。そこで、表示幅に小数点以下の値が含まれていても、いずれかの条件に該当するようにメディアクエリの指定を見直すことにしました。その結果、767pxで発生していた表示崩れは一旦解消しました。

しかし、今度はメディアクエリをどのように記述するのが適切なのか、という疑問が残ります。小数点以下の値を考慮して指定する方法や、notを使って条件を指定する方法など、いくつかの選択肢が考えられたため、コーディングの先輩に相談してみることにしました。

比較演算子を使ったメディアクエリ

メディアクエリの書き方について相談したところ、先輩から教えていただいたのが、比較演算子（不等号）を使った新しい構文です。従来のmin-widthやmax-widthを使う書き方と比べて、画面幅の条件を直感的に読み取れる点が魅力的です。

例えば、比較演算子を使うと、次のように記述できます。

CSS 
/* デスクトップ向け */
@media (width >= 768px) {
  /* 画面幅が768px以上のスタイル */
}

/* モバイル向け */
@media (width < 768px) {
  /* 画面幅が768px未満のスタイル */
}

この書き方なら、条件と適用範囲の関係がひと目でわかります。また、notを使った書き方と比べて、画面幅を3つ以上の範囲に分けたい場合に条件を整理しやすく、記述を簡潔にできる点も優れています。

ぜひ採用したいと思いましたが、気になったのはブラウザの対応状況です。どれほど便利な構文でも、閲覧者のブラウザで動作しなければ意味がありません。新しい技術を取り入れる際には、使いやすさと互換性のバランスを考える必要があります。

そこで先輩が教えてくれたのが、「Can I use」というWebサイトです。このサイトでは、HTMLやCSS、JavaScriptなどの機能について、ブラウザやバージョンごとの対応状況を確認できます。実際にMedia Queries: Range Syntaxの対応状況を開き、比較演算子を使った構文がどのブラウザで利用できるのかを調べてみました。

ブラウザの利用シェアから採用を判断する

Can I useでは、各ブラウザの対応状況だけでなく、ブラウザの利用シェアをもとに、機能を利用できる環境がどれくらいあるのかも確認できます。未対応のブラウザが存在していても、その利用シェアが十分に小さければ、新しい構文を採用する判断ができると考えました。

比較演算子を使った構文に対応していないのは、Internet Explorerのほか、古いバージョンのChromeやEdge、Safari、Firefoxなどです。一方、同ページの2026年9月時点の統計では、対応ブラウザの日本国内での利用シェアは約94.36%に達していました。

この結果から、未対応のブラウザの利用シェアは十分に小さいと考え、rat daysでは比較演算子を使った新しい構文を採用する判断をしました。しかし、対応していないブラウザを利用するユーザーが一定数存在することも無視できない事実です。今後は従来のメディアクエリを併用するなど、より多くの環境で正常に表示できる方法を検討したいと思います。

まとめ

今回の問題は、メディアクエリの指定を見直すことで解決できましたが、調査を進めるなかで、CSSの書き方にも複数の選択肢があることを知りました。特に、比較演算子を使った構文は、条件を直感的に理解しやすく、複数の画面幅に対応する際にも記述を整理しやすい点が魅力的でした。

一方で、新しい構文を採用するかどうかは、書きやすさだけで決められるものではありません。今回のようにブラウザの対応状況や利用シェアを調べることで、利便性と互換性の両方を考慮した判断ができます。これからも、問題を解決するだけで終わらせず、より読みやすく、保守しやすいコードを書くための方法を学んでいきたいと思います。
